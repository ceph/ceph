
* Include fdb.h for the complete public interface. Lower-level ownership lives
  in base.h; transactions, transactors, and staged output live in transaction.h;
  direct key operations live in interface.h; and range traversal lives in
  scan.h.

----
Network, Database, and Transaction Options:

The network_options, database_options, and transaction_options
aliases use owning option_list sequences. Every entry applies in written order,
including repeated codes. This replaces option_map and its map-style interface;
operator[] is unavailable. See EXAMPLES.md, "Options", for the
breaking-change notice, insertion and replacement rules, and migration examples.
Core and both experimental async backends share application and replay semantics.

FoundationDB defines option values and limits in its generated API (application programming interface)
documentation and source file fdbclient/vexillographer/fdb.options. Value validation belongs to
FoundationDB; it can report errors when setting an option or on a later request.

----
Range Request Options:

query::query_options::streaming_mode uses FoundationDB's FDBStreamingMode
constants directly, with FDB_STREAMING_MODE_ITERATOR as the default. There is
no separate libfdb streaming-mode enum. Query options configure individual range
requests; transaction options configure transactions and their replay state.
See query.h and EXAMPLES.md, "Scanning And Traversal", for the current interface.
