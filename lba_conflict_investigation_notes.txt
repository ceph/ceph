LBA conflict investigation - how to run store_bench + measure conflicts
=========================================================================

1. Rebuild after any cache.cc/cache.h changes:

   ninja bin/crimson-store-bench

2. Reset the store-bench scratch directory before each run:

   ./reset_store_bench_dir.sh

3. Run the benchmark with the relevant metrics tracked. `random_write`
   is the workload that actually exercises LBA-tree conflicts.

   ./build/bin/crimson-store-bench --store-path store_bench_dir --smp 4 --duration 10 \
     --work-load-type random_write --seastore_device_size 10G \
     --track-metrics "cache_trans_invalidated_by_extent,cache_lba_conflicts_mergeable,cache_lba_conflicts_overlapping" \
     > lba_conflict_mergeable_run3.json

   (Earlier runs, before the mergeable/overlapping counters existed,
   only tracked cache_trans_invalidated_by_extent to get the plain
   conflict rate.)

4. Feed the JSON into lba_calculation.py to get the mergeable %:

   python3 src/crimson/tools/store_bench/lba_calculation.py lba_conflict_mergeable_run3.json
